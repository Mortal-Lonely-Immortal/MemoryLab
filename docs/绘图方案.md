## 2. 基础图元

所有 UML 符号都由下面六个基础图元组合：

```python
cv.rect(x, y, w, h, fill, stroke)              # 矩形、类框、表框、控制焦点
cv.line(x1, y1, x2, y2, stroke, dash="8 6")    # 线、生命线、关系线
cv.polygon([(x,y), ...], fill, stroke)         # 箭头、空心/实心菱形、三角
cv.ellipse(cx, cy, rx, ry, fill, stroke)        # 椭圆：用例、角色头
cv.polyline(pts, stroke, sw)                    # 折线：自关联、绕行
cv.text(x, y, "文字", size, color, anchor="lm") # 文字
```

常见组合：

| UML 元素 | 组合方式 |
|---|---|
| 类框三格 | 1 个矩形 + 2 条横线 + 3 段文字 |
| 继承/实现三角 | 三点 polygon，填充白色 |
| 组合/聚合菱形 | 四点 polygon，黑/白填充 |
| 生命线 | line + `dash="10 8"` |
| 控制焦点 | 14px 宽窄矩形 |
| 自关联消息 | 三折 polyline + 箭头 |
| 时序消息文字 | 白底 label，避免压住生命线 |
| ER 表 | 表头矩形 + 字段行文字 + PK/FK 标注 |

## 3. 布局规则

### 类图：手动坐标

类图不自动排版。类框坐标直接写死，同一关系尽量共线：

- 继承/实现：子类放父类正下方，画垂直线。
- 组合/聚合：整体与部分同列或同行，菱形在整体一端。
- 依赖：用虚线箭头，走右侧或下方空白通道。
- 框高按内容算：

```text
38 + 10 + 属性数×25 + 8 + 方法数×25 + 8
```

当前类图显式分四层：Controller、Service、Mapper、Entity，四层各有浅色容器。  
Mapper 层放 `CardMapper`、`DeckMapper`、`NoteMapper`、`ReviewLogMapper`、`FsrsParamMapper`，每个都标 `«interface»`；字段/方法、虚线依赖、`maps` 关联都要保留，不要让 Mapper 只以空框或字段形式出现。

### 时序图：数据驱动

只填 `participants` 和 `messages`，`seqkit.render()` 自动排版：

- 横坐标等分：`120 + (width-240)*i/(n-1)`
- 纵坐标每条消息 +60，自关联 +82
- 控制焦点按每个参与者的首末消息自动计算
- 支持 `sync` / `ret` / `self`，可扩展 `alt` 组合片段

### 其他图：先分层，再落坐标

- 架构图：Windows 客户端 / 本地服务 / 本地数据三层，容器内再放框。
- 用例图：系统边界内单列用例，左侧学习者，右侧外部服务；外部服务走边界外的竖向总线，避免连线穿过用例。
- 关系图：核心链横排（用户→卡组→知识点→卡片→复习记录），分支竖排；文档链放底部。
- 概念模型图（ER）：实体用矩形，联系用菱形；核心实体横向排列，关系画在实体之间，不展开物理字段。
- 物理表结构图：核心表左侧纵向链，方法链 2×2 排列，文档库单独一张；字段行带中文注释。

## 4. 用例图与时序图专用流程

这两张图最容易“看起来能画，实际全是线穿字”。下面按当前 MemoryLab 脚本的实际坐标记录。

### 4.1 用例图：手写坐标

当前画布和元素：

| 元素 | 当前坐标 / 尺寸 |
|---|---|
| 画布 | `1600 × 1000` |
| 系统边界 | `x=430, y=65, w=750, h=860`，`dash="9 7"` |
| 系统标题 | `(805, 92)`，边界内部顶部 |
| 用例椭圆 | 中心 `x=805`，宽 `600`，高 `50` |
| 用例纵坐标 | `cy = 190 + i*50` |
| 学习者 | `(180, 480)` |
| 外部服务 | `(1370, 480)` |
| 外部服务总线 | `x=1210`，`y=500..870` |

**为什么是 50**：椭圆高 50，纵向紧贴排布。  
15 个用例占 `190..890`，边界 `65..925`，上下都留出空间。

**关键写法：连线接左右顶点**：

```python
ucs.append((cy, 805 - 300, 805 + 300))
cv.line(205, 500, l, cy, LINE, 1.0)       # 学习者 -> 左顶点
cv.line(1210, cy, r, cy, "#6B4410", 1.2)  # 总线 -> 右顶点
```

不要用“椭圆交点公式”逐点求交：

- 公式写错时线会飞出画布；
- 把整列中心当椭圆中心时，11 条线会重合成一条；
- 接左右顶点最稳，且所有线都落在左右两个走廊里。

**外部服务走边界外总线**：

```text
外部角色(1370,480)
   │
   └── 水平到 x=1210
          │
          ├── 竖向到“简化教程”的 y
          ├── 竖向到“AI 导师答疑”的 y
          └── 竖向到“DeepTutor 工作台”的 y
```

这样外部线不会从系统内部穿过用例。

**角色是 7 笔**：

```python
ellipse(头) + line(身体) + line(手臂) + line(左腿) + line(右腿)
+ text(角色名) + text(<<stereotype>>)
```

**用例顺序**：`导入 → 提取 → 简化 → 生成卡 → 复习 → 管理 → 统计 → 方法 → 导师 → 划线提问 → 导师生成卡片 → 配置 → DeepTutor → 回忆卡片 → 文言白话改写`。  
`cy = 190 + i*50`，y 轴向下，所以第一个用例在最上面；不要写成 `top - i*step`。

### 4.2 时序图：数据驱动

只填两组数据：

```python
parts = [
    {"name": "学习者", "kind": "actor"},
    {"name": "P5 前端", "kind": "object", "color": BLUE},
    {"name": "Flask 文档服务", "kind": "object", "color": ORANGE},
    {"name": "LLM 服务", "kind": "object", "color": RED},
    {"name": "Spring Boot", "kind": "object", "color": GREEN},
    {"name": "H2 / MySQL", "kind": "object", "color": PURPLE},
]

msgs = [
    {"kind": "sync", "f": 0, "t": 1, "text": "1  上传 PDF/Word/PPT"},
    {"kind": "self", "f": 2, "text": "3  保存 uploads，写 document"},
    {"kind": "ret",  "f": 2, "t": 1, "text": "4  返回 doc_id"},
    ...
]
```

`seqkit.render()` 负责三件事：

```text
① 横坐标：xs = 130 + (width-260)*i/(n-1)
② 纵坐标：y=225 开始；普通消息 +60，自关联 +82
③ 控制焦点：按每个参与者的首末消息自动算 span
```

当前参数：

```text
width=1800
step=60
self_step=82
font=18
6 个参与者
20 条消息
```

**为什么自关联要 +82**：自关联折线要向右折、向下折再回来，需要额外的纵向空间；普通消息只占一条线。

**三类消息**：

| kind | 画法 |
|---|---|
| `sync` | 实线 + 实心箭头 |
| `ret` | 虚线 + 箭头 |
| `self` | 右→下→左三折线 + 箭头 |

**标签必须加白底**：

```python
cv.label(tx, y - 16, text, 18, INK)
```

否则长消息会压住生命线虚线，看起来像“给生命线划线”。

**控制焦点不能手动画**：

```python
for idx, (a, b) in span.items():
    cv.rect(xs[idx]-7, a-12, 14, b-a+26, C_BAR, C_BAR_EDGE, 1.0)
```

`span` 是每个参与者第一次和最后一次出现的消息 y 坐标；这样激活条自动包住它的消息。

**绘制顺序**：

```text
组合片段 → 生命线 → 控制焦点 → 消息 → 标签
```

因为 SVG 后画的会盖住先画的；如果先画白底标签、后画激活条，激活条会把白底盖掉，文字又压回线上。

**分支片段**（当前 Memory Lab 时序图没有使用，但 `seqkit` 支持）：

```python
frames = [{
    "from": 10, "to": 13,
    "tag": "alt",
    "cond": "[LLM 已配置]",
    "sections": [{"at": 12, "label": "[LLM 超时/未配置]"}],
}]
```

## 6. 自检流程

每张图生成后必须做：

1. 重跑脚本，确认 SVG 没有报错；
2. Edge 截图，读 PNG；
3. 检查以下四项：
   - 文字是否压线、压框、被裁切；
   - 箭头是否指向正确对象，是否穿过文字；
   - 关系线是否正交，是否从对象边缘出发；
   - 图在 15 cm 宽时文字是否仍可辨认。
4. 有问题改坐标/字号/走线，再重跑。

本项目的实际修正记录：

| 问题 | 改法 |
|---|---|
| 用例图上方用例被裁掉 | `cy` 改为 `top + i*step`，不要把 y 轴方向写反 |
| 外部服务连线穿过用例 | 在系统边界外增加竖向总线，再分支到目标用例 |
| 架构图 LLM 框压住 Windows 容器 | 把 LLM API 移到本地服务容器右侧独立区域 |
| 关系图标签悬空 | 标签放到卡片正下方，用垂直线连接 |
| 文档块虚线穿过计划条目 | 走 `x=860` 的空白通道，从知识点右侧进入 |
| 类图 ImportService 箭头穿过 FsrsService | 从右侧 `x=1450` 绕行，再向下进 ImportService |
| 类图 ImportService 到 Card 穿过 ReviewLog | 走画布底部 `y=980` 的通道，从 Card 底部进入 |

## 7. 风格约定

- 白底 + 浅色填充；同色系边框加深。
- 箭头优先正交（先横后竖），必须斜线时文字加白底。
- 一图一事；元素超过 15 个时先分层，不要堆在一个平面。
- 中文用微软雅黑，代码/端口用等宽字体。
- 图题不画进 SVG，由 Word 的 `Caption` 样式统一编号。
- Word 中按 14.6 cm 宽插入；图片本身保留 2x 分辨率，放大查看不糊。
- 六类图的编号和 SRS 章节对应关系见上表。
