# 卡片批量删除与自动分类设计

## 1. 目标

- 卡片最右侧出现多选框；
- 支持全选本页、全选筛选结果；
- 支持删除选中、按当前分类删除；
- 卡片按“书 → 章节”自动分类；
- 不新增重复的 book/chapter 字段，复用现有 `deck.parent_id` 层级。

## 2. 分类模型

```text
book deck (parent_id = 0)
  └─ chapter deck (parent_id = book deck)
       └─ card.deck_id
```

示例：

```text
计算机网络
  ├─ 第1章 网络概述
  ├─ 第2章 物理层
  └─ 第3章 数据链路层
操作系统原理
  ├─ 第1章 操作系统引论
  └─ 第2章 进程管理
```

### 书名来源

导入的 docx 中通常有：

```text
来源：教材翻译 计算机网络.pdf · 第1章 网络概述
```

优先从 `教材翻译 <书名>.<扩展名> ·` 提取书名；提取不到时用上传文件名；仍为空则归入“未分类”。

### 章节来源

优先从来源行提取 `第 N 章 <章节名>`；否则使用 `note.chapter` 的数字/实验/附录标记。

## 3. 自动分类时机

1. **导入时**：`ImportService` 创建 note 前调用 `CardClassificationService.ensureBookChapter()`；
2. **启动时**：`ClassificationBootstrap` 对旧 note 做一次幂等回填，把已有卡片移到新层级；
3. **手动**：卡片页 `AUTO CLASSIFY 自动分类` 调用 `POST /api/v1/cards/reclassify`。

## 4. 批量删除接口

```http
POST /api/v1/cards/batch-delete
{ "ids": [1, 2, 3] }

POST /api/v1/cards/batch-delete-filter
{
  "bookId": 12,
  "deckId": 34,
  "keyword": null,
  "state": null,
  "favorite": null,
  "wrong": null
}

POST /api/v1/cards/reclassify
```

- `batch-delete`：按 ID 删除，最多一次提交当前选择；
- `batch-delete-filter`：按当前筛选条件删除整个分类；
- 都是逻辑删除，`deleted=1`，不物理删除复习流水；
- 删除后 `deck.card_count` 由 `DeckService.list()` 动态汇总。

## 5. 筛选接口

```http
GET /api/v1/cards?page=1&size=20&bookId=12&deckId=34
```

- `bookId`：包含书 deck 本身及其直接章节 deck；
- `deckId`：精确到章节；
- 两者可以同时使用；
- 原有 `keyword/state/favorite/wrong` 继续有效。

## 6. 卡片页交互

```text
[搜索] [全部书籍] [全部章节] [状态] [收藏/错题]
[✓ 全选本页] [全选筛选结果]
[删除选中 (N)] [删除当前分类] [自动分类]

BOOK / CHAPTER
  [卡片] ... [编辑] [暂停] [删除] [✓]
```

- 复选框在卡片最右侧；
- 分组标题显示“书 / 章节”；
- 分类删除要求先选书/章节或设置筛选条件，避免误删全部；
- 删除前显示分类和数量确认。

- [ ] 每张卡右侧有复选框；
- [ ] 全选本页/全选筛选结果可用；
- [ ] 删除选中后总数减少；

- [ ] 自动分类重复执行不会创建重复 deck。
