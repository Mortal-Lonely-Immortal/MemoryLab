# 定靶子与砍量

学之前必须先知道"为什么要学这些"，否则每一节都只是碎片。这份规则管三件事：问什么、怎么砍、挂在哪条主线上。

## 先问三件事

1. **目标**：什么岗位、什么类型的公司（互联网大厂 / 央国企 / 外企 / 创业公司）
2. **经验**：校招无经验 / 1–3 年 / 3 年以上
3. **时间**：离 deadline 还有多久

用户没说清就先问，问完再定范围。**没有靶子不定范围**——定了也是照抄目录。

## 靶子决定砍量

拿到材料后先做三级分类，再决定学什么：

| 分级 | 判据 | 处理 |
|---|---|---|
| 必背 | 能脱稿讲 60 秒 | 主战场，逐节做讲义 |
| 懂概念 | 能说清是什么、为什么，不记细节 | 一次过，不单独出题 |
| 不看 | 有经验的人才用得上 | 直接跳过，标注理由 |

砍量发生在学习之前，不是学完再想"为什么要学"。

同一节在不同靶子下分级不同：`分库分表` 对社招是必背，对校招是不看；`AQS 源码` 对大厂必背，对央国企只是懂概念。

## 主线：让碎片连起来

知识点挂在一条数据流上才叫系统。三条常用主线：

- **请求生命周期**（后端通用，最推荐）：浏览器 → 框架（路由/Bean/AOP）→ 线程池 → ORM → 数据库 → 返回 → JVM 里对象的生死
- **故障排查**（有工作经验时用）：线上 OOM / 慢 SQL / 死锁，从现象倒推机制
- **性能优化**（高级岗）：QPS 从 100 到 10000，每一层瓶颈在哪

选一条主线，然后让每一节回答"我在主线的哪一环"。答不上的，要么删掉，要么说明它确实是孤立知识。

## 知识地图

定靶子后先产出 `知识地图.md`，再开始讲：

```markdown
# <主题> 知识地图

## 主线
<一句话描述这条数据流>

## 章节挂载
| 章 | 在主线上回答什么 | 脱离主线会变成 |
|---|---|---|

## 分级
- 必背：N 节
- 懂概念：N 节
- 不看：N 节（逐条列理由）
```

地图先行，讲义在后。地图是"为什么学"，讲义是"怎么学"。

## 反例

- 拿到材料直接按章节顺序讲 → 用户会觉得碎片化
- 每节都讲得很细，但没有主干 → 学完记不住
- 不问靶子就砍量 → 砍错，或者一节都不敢砍
