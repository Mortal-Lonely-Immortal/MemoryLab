# 三种材料的入口

同样是"学懂"，三种材料的做法差别很大。先判断类型，再走对应入口。

三种材料都跑同一套流程（定范围 → 术语表 → 讲解 → 配图 → 一页纸复述 → 出题 → 记录 → 下次），差别只在中间几步的侧重和检查方式。

## 课本 / 讲义（知识为主）

**特点**：结构完整、有定义、有例题，缺的往往是动机——为什么要学这个。

**做法**：

1. 先看目录和章末小结，用两句话说出这章在解决什么问题
2. 术语表按"定义 / 为什么需要它 / 什么时候用它"三列写
3. 讲解顺序：直觉 → 准确表述 → 例题 → 反例
4. 配图优先画"概念之间的关系"，不要画章节树

**检查表**：

- [ ] 能说出这章解决了什么问题
- [ ] 每个术语都写了"为什么需要它"
- [ ] 至少一个反例说明什么时候不适用

**常见坑**：把目录抄成知识点清单；逐段总结却不给例子；把教材的严谨表述直接搬过来，没有通俗版。

## 老师 PPT（提炼为主）

**特点**：是提纲不是讲义，逻辑跳跃多，图比字重要。

**做法**：

1. 先列出全部 slide 标题，标出哪些是承接、哪些是跳跃
2. 跳跃处补推理，并标 `[推断]`
3. 一页出现多个结论时拆成几节，每页只留一个结论
4. 先描述 slide 上的图，再解释它想说明什么
5. 跳过"谢谢 / Q&A / 谢谢观看"这类补充页

**检查表**：

- [ ] 能画出 slide 之间的逻辑链
- [ ] 每个跳跃处都有 `[推断]` 标注
- [ ] 没有"第 X 页讲了……"式的页码索引

**常见坑**：逐页复述；把自己的补充当成老师原话；把 PPT 的要点当完整知识，缺推理也不补。

## 项目源码（理解为主）

**特点**：没有"教材"，入口是运行和调用链；代码量大，不能全读。

**做法**：

1. 先给模块图（谁依赖谁），标出入口文件
2. 选一条主调用链，从头走到尾
3. 每个关键函数回答三个问题：为什么存在 / 谁调用它 / 什么情况会出错
4. 能跑就跑：改一个参数，看输出怎么变
5. 不贴大段代码，只贴关键 3–5 行

**检查表**：

- [ ] 有一张模块图，标了入口
- [ ] 能说清一条主链路的完整流程
- [ ] 每个关键函数回答了三个问题
- [ ] 至少做过一次运行验证

**常见坑**：从 main 逐行读到尾；贴一整段代码当讲解；只讲"做了什么"不讲"为什么存在"。

## 判断材料类型

用户没说清时，按这个顺序判断：

1. 有页码、章节号、例题 → 课本
2. 有 slide 编号、大量图、条目化 → PPT
3. 有文件路径、函数名、可运行 → 源码

混合材料（比如 PPT + 讲稿）按主体判断，另一部分作为补充证据。
